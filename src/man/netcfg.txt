netcfg - network setup that survives reboots

SYNOPSIS
  netcfg [status]
  netcfg auto [DNS]
  netcfg static IP/BITS [GATEWAY|- [DNS]]
  netcfg dhcp | wizard | off | test

DESCRIPTION
  OC2 computers reach the internet through an Internet Gateway block on the
  same network connector, using a network interface card. Behind the gateway
  there is no DHCP and no DNS, so the address is set by hand. netcfg writes
  the eth0 stanza of /etc/network/interfaces (kept across reboots), writes
  the name server (/etc/resolv.conf is a RAM file, so it is re-created
  whenever eth0 comes up) and brings eth0 up.

  auto      10.0.0.2/24 with gateway 10.0.0.1 and name server 1.1.1.1. The
            gateway answers on whatever address the default route points
            to, so this works anywhere; give each computer its own address
            with `netcfg static 10.0.0.3/24` etc.
  static    your own address; GATEWAY defaults to .1 of the subnet, "-" for
            none (an in-game LAN only); DNS defaults to 1.1.1.1
  dhcp      for computers on a network where another computer runs a DHCP
            server (see wizard)
  wizard    OC2's interactive setup-network.lua, which can also turn this
            computer into the DHCP server for the others
  off       removes the eth0 setup
  test      checks the address, route, gateway ping, DNS, a connection to
            Anthropic's API address and HTTPS to GitHub

NOTES
  Server admins can block hosts or disable the gateway. Connections only go
  outwards; nothing on the internet can connect in. Chunk unloads and server
  restarts drop open connections.
