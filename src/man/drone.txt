drone - robots as drones in the swarm

SYNOPSIS
  drone status | move DIR [N] [--dig] | turn left|right|around | face DIR
  drone go X Y Z [--dig] | home [--dig] | dig [SIDE] | place [SIDE]
  drone inspect [SIDE] | scan | calibrate
  swarm drones                       (on any swarm computer: every drone)
  swarm drone NAME COMMAND...        (send a drone command, wait for the result)

WHAT A DRONE IS
  An OC2 robot running Shulker OS. It talks to the swarm through a drone base:
  a swarm worker with network tunnel cards. Each tunnel card is linked to the
  tunnel module of one drone (a computer has up to 4 card slots: one network
  card for the swarm plus up to 3 tunnel cards, so 3 drones per base; use more
  bases for more drones).

SETTING ONE UP
  The robot: CPU, memory, the "Shulker Drone" hard drive (data pack), a
  network tunnel module, and the modules it needs: block operations (digging,
  placing), inventory operations, scanner. Place a charger where the robot
  starts: that spot is home (0 0 0).
  Link the tunnel module and a network tunnel card: use (right-click) one
  while holding it and insert the other.
  The base: a swarm worker with that tunnel card (and its network card), set
  up with `swarm base` (or "Drone base" in the setup wizard). It gives each
  link its own network 10.43.K.0/24, hands the drone an address and passes
  its traffic on to the main computer.
  Power on the robot: it gets its address from the base, joins the swarm and
  shows up as drone1, drone2, ... in `swarm drones` and `swarm top` (under
  its base). Without the Shulker Drone drive, type on the robot:
      udhcpc -i eth0 && wget -qO- http://10.43.1.1/join | sh
  (10.43.1.1 is the first link of the base; `swarm base` prints the address.)

COMMANDS
  Positions are relative to the start: x grows east, y up, z south (OC2's
  robot compass). From any swarm computer:
      swarm drone drone1 status
      swarm drone drone1 go 10 0 -5 --dig
      swarm drone drone1 scan
      swarm drone drone1 home
  Longer work: a script run as a job, e.g.
      swarm submit --on drone1 'drone move forward 8 --dig; drone home'

SAFETY
  Below 15% energy a drone stops waiting and drives home (to its charger) by
  itself, digging if needed; it does that again only after charging above 50%.
  `go` without --dig never breaks blocks: it reports where it got stuck.

WORK
  drone origin X Y Z           where its charger spot is in the world (F3);
                               go and mine then use world coordinates
  drone mine X1 Y1 Z1 X2 Y2 Z2 dig out the box layer by layer, top first;
                               goes home to charge below 20 % and returns
  Usually given as orders from the main computer: see `man control`.

CLEARING BIG AREAS
  Given as an order on the main computer (control, or swarm order):
      clear chunks CX CZ SIZE [TOP BOTTOM]    SIZE x SIZE chunks, starting at
                                              chunk CX CZ (F3: "Chunk: x y z")
      clear X1 Z1 X2 Z2 [TOP BOTTOM]          a box in world coordinates
  TOP and BOTTOM default to 128 and -59 (bedrock below). The main splits the
  area into chunk columns and hands each free drone one, top to bottom in
  bands of 9 layers; a drone keeps its chunk until the bottom. Progress is
  saved: the order survives restarts of the main. A failed band goes to
  another drone (3 tries); a drone failing twice in a row pauses 10 min.

  Each drone needs:
    origin            drone origin X Y Z (its charger spot, F3) - required
    block operations  module, plus pickaxes in its inventory (spares are used
                      when one is worn down to 8 durability; the worn one is
                      kept for repair)
    inventory ops     module, plus a dump block in its inventory: a trash can
                      (deletes what it digs) or an ender chest (sends it to
                      your base). Full inventory -> it places the dump block
                      above itself, empties into it, digs it back up.
                      Without one it flies home and empties into a chest
                      north of its charger; it never drops items on the ground
    free column       the blocks above the charger up to the travel height
                      (drone travel Y, default charger + 3): long trips go up
                      or down to that height, across, and straight down, so
                      they don't cut through the base
  drone check shows what is missing.

  Speed: about 2,400 blocks an hour per drone (3 layers per pass). 25 x 25
  chunks from y 128 down to -59 are ~30 million blocks: about 520 days for
  one drone, ~10 days for 50, ~5 days for 100. The area must stay loaded
  (force-load it); a drone in an unloaded chunk stands still.
